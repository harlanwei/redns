has_resp

Returns true when an earlier rule has produced a response for the current query. The cornerstone of “answer if you can, otherwise fall through” chains.

matcher used in: matches

Usage

Takes no arguments. Typically paired with accept to stop the chain once a response exists:

- matches: has_resp
  exec: accept

Parameters

Parameter Required Type Default Description
— No none n/a This matcher takes no arguments.

Details

  • A response can come from cache, hosts, black_hole, forward, or any other action that set one.
  • The inverse — !has_resp — matches only when no response exists yet; the typical guard before forwarding.

Examples

- exec: "$cache"
- matches: has_resp
  exec: accept
- exec: "$forward"

See also

  • has_wanted_ans — a response with answers.
  • accept — stop the chain keeping the response.
