qname

Matches the query name against a set of domain patterns. This is the workhorse of blocking and routing rules.

matcher used in: matches

Usage

Write qname followed by space-separated domain expressions. A bare domain matches the domain itself and all subdomains. Expressions may carry a type prefix. 

matches: qname example.org
matches: "qname google.com domain:internal.example full:exact.example keyword:ads regexp:^cdn[0-9]+\.example"

Parameters

Parameter Required Type Default Description
expressions Yes string (space-separated tokens) — Domain patterns. Bare example.com = subdomain match (the domain and all subdomains). Prefixes: domain: subdomain (explicit), full: exact, keyword: substring, regexp: regex. &path loads one pattern per line from a file.

Details

  • Matching is case-insensitive; leading/trailing dots are stripped before comparison.
  • Files loaded with & are read at startup; blank lines and lines starting with # are ignored.
  • The trie-based matcher looks up labels in O(labels) regardless of list size — large blocklists are cheap.
  • An empty argument never matches — use has_resp if you need a positive default.

Examples

- matches: qname example.org
  exec: black_hole 0.0.0.0

- matches: "qname &/etc/redns/ads.txt"
  exec: drop_resp

See also

  • domain_set — reusable named domain sets.
  • cname — match CNAME targets instead.
  • redirect — rewrite the query name.
