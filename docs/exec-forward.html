forward

Forwards the query to one or more upstream resolvers. This is how ReDNS actually resolves names — the plugin at the end of most chains.

executable used in: exec

Usage

Quick form — space-separated upstream addresses (plain host:port means UDP):

- tag: forward
  type: forward
  args: "1.1.1.1 8.8.8.8 tls://9.9.9.9:853"

Full form — YAML with per-upstream options:

- tag: doh
  type: forward
  args:
    upstreams:
      - addr: "https://dns.google/dns-query"
        tag: google
        dial_addr: "8.8.8.8:443"
        bootstrap: "1.1.1.1"
      - addr: "quic://1.1.1.1:853"
    concurrent: 3

Parameters

Parameter Required Type Default Description
upstreams Yes list of maps — The upstream list. Each entry: {addr, tag, dial_addr, bootstrap, pool_max_idle} (see below).
addr Yes string (scheme://host:port) — Upstream address with any supported scheme: udp://, tcp://, tls://, https://, quic://, h3://. Bare host:port means UDP. See Upstreams for the protocol table.
tag No string absent (no label) Optional label surfaced in metrics and the dashboard's upstream view.
dial_addr No string (IP or IP:port) absent (resolve hostname) Connect to this IP:port instead of resolving the hostname. Port defaults per scheme (53/853/443). Useful when the system resolver is unavailable.
bootstrap No string (host:port) absent (system resolver) DNS server used to resolve the upstream hostname (for DoH/DoT).
pool_max_idle No integer absent (16 UDP / 4 conns) Per-upstream cap on idle pooled connections/sockets. Can also be set once at the forward level to apply to all upstreams.
concurrent No integer 1 (YAML) / 3 (quick) How many upstreams are queried at the same time; the best (lowest-latency) response wins. Combines with the latency-aware selection.
subprocess_suffix No string absent (disabled) Suffix for an out-of-process upstream that speaks DNS over a Unix socket. An advanced integration point for custom resolvers.

Details

  • Upstreams are scored by EMA latency and consecutive error streaks; healthy, fast upstreams are preferred.
  • DoT pipelining (RFC 7766) is probed at startup so queries can share one TLS connection.
  • A UDP response with the TC flag is retried over TCP automatically.
  • DoH requests use a browser-like User-Agent and fall back from GET to POST for long queries.
  • If every upstream fails to respond, the chain continues — a later rule (or the best_effort option) can still handle the query.
