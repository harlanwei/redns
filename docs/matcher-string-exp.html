string_exp

Applies a string operator to a source value: an environment variable or server metadata such as the request URL path.

matcher used in: matches

Usage

matches: string_exp $PATH contains /usr
matches: string_exp url_path zl

Format: string_exp <source> <op> [values…].

Parameters

Parameter Required Type Default Description
source Yes string — Where to read the string from: $ENV_VAR (environment variable, read at startup), url_path (request URL path from server metadata), or server_name (server name from metadata).
op Yes string — Operator: zl (value is zero-length), eq (equals any value), prefix, suffix, contains, regexp (any value is a regex that matches).
values Optional string (space-separated) none (required except zl) One or more comparison strings. Required for every operator except zl; for eq/prefix/suffix/contains the matcher fires if any value matches, and for regexp if any value matches as a regex.

Details

  • The $ENV_VAR source is read when the config loads (like env); the metadata sources are evaluated per query.
  • url_path and server_name are populated from server metadata — useful in advanced/embedded deployments that inject request context.

Examples

# Match when the URL path is empty (root request)
- matches: string_exp url_path zl
  exec: accept

# Match when PATH ends with /bin or /sbin
- matches: string_exp $PATH suffix /bin /sbin
  exec: reject

See also

  • env — the simple set/equals variant.
