Rules

All query processing happens in sequence plugins: an ordered list of rules evaluated for every query. This page explains the rule syntax; the Plugins section documents every matcher and executable.

A sequence rule

plugins:
  - tag: main
    type: sequence
    args:
      - matches: qname example.org
        exec: black_hole 0.0.0.0
      - matches: ["qtype 1 28", "!has_resp"]
        exec: "$forward"
Parameter Required Type Default Description
matches No string or list of strings always fires Matcher directives. When several are given, all must match (logical AND) for the rule to fire. Prefix any directive with ! to negate it. A missing matches fires unconditionally.
exec Yes string — The action to run: a built-in type with arguments (black_hole 0.0.0.0) or a reference to a named plugin ($forward).

Referencing named plugins

Any plugin declared with a tag can be referenced with a $ prefix — in matches (for matcher plugins like domain_set) and in exec (for executable plugins like forward or sequence). 

- tag: blocklist
  type: domain_set
  args:
    files: ["/etc/redns/ads.txt"]

- tag: main
  type: sequence
  args:
    - matches: "$blocklist"
      exec: black_hole 0.0.0.0

ReDNS builds plugins in dependency order — non-sequence plugins first, sequences last — so inter-plugin references always resolve, regardless of the order in the file.

Chain flow

  • Rules run top to bottom. A rule fires only when all its matchers pass.
  • Executables run in order until one stops the chain: accept, reject, or any action that produced a response (for example a cache hit).
  • The “response” that matchers inspect is whatever earlier rules have produced so far — this lets you compose conditions like “has a response and it is a SERVFAIL”.
  • When the chain ends without a response, the server returns an empty NOERROR answer.
  • Recursive executables (redirect, use-answer-of, fallback, cache…) can rewrite the query and pass control back to the chain.

Common pitfalls

  • Quotes inside matcher arguments are not stripped by the parser. Write matches: qname example.org, not matches: qname "example.org". Use YAML-level quoting when the value must stay a single string: matches: "qname example.org example.com".
  • Matcher arguments are space-separated tokens. Multi-word expressions (like regexes with spaces) belong in a file loaded with &file or the files option.
  • A rule that fires does not stop the chain by itself — add accept after actions that set a response, or later rules may override it.
