cache

A sharded LRU response cache with lazy stale-while-refresh, request coalescing, and optional on-disk persistence. Placed before forward, it answers most repeat queries without touching an upstream.

executable recursive used in: exec

Usage

Quick form — entry count only:

- tag: cache
  type: cache
  args: 65536

Full form — with disk persistence:

- tag: cache
  type: cache
  args:
    size: 65536
    cache_file: /var/lib/redns/cache.bin
    dump_interval: 300

Parameters

Parameter Required Type Default Description
size No integer 0 LRU capacity in entries. 0 disables caching (the plugin becomes a pass-through).
cache_file No string (path) absent (in-memory only) When set, the cache is dumped to this file every dump_interval seconds and on graceful shutdown, and restored at startup. A missing or corrupt file simply starts an empty cache.
dump_interval No integer (seconds) 300 Period between automatic disk dumps when cache_file is set.

Details

  • Sharded LRU — bounded memory and low lock contention; entries expire by TTL.
  • Lazy refresh — a stale entry is served immediately while a background refresh fetches a fresh copy (up to 30 s of staleness tolerated).
  • Coalescing — concurrent misses for the same key trigger a single upstream query.
  • Cache keys are lowercased qname + qtype; responses are stored with normalized TTLs and patched in place on hits.
  • On a hit the plugin sets the response — follow it with matches: has_resp + accept to stop the chain.

See also

  • forward — usually placed right after the cache.
  • ttl — control how long records stay cached.
  • reverse_lookup — a separate, specialized cache.
