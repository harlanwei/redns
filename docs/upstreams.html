Upstreams

Upstreams are configured in the forward plugin. This page documents the supported transport protocols and how addresses are written.

Transport protocols

Scheme Default port Description
udp://host:port 53 Plain UDP with socket pooling and response-ID filtering. Bare host:port addresses default to this scheme.
tcp://host:port 53 Plain TCP with connection pooling and transparent retry on stale connections.
tls://host:port 853 DNS-over-TLS (RFC 7858): TLS session cache, connection pooling, RFC 7766 query pipelining (probed at startup).
https://host/path 443 DNS-over-HTTPS (RFC 8484): HTTP/2, GET and POST, browser-like User-Agent, automatic POST fallback for long queries.
quic://host:port 853 DNS-over-QUIC (RFC 9250): one query per QUIC stream.
h3://host/path 443 DNS-over-HTTP/3: DoH semantics over the QUIC transport. 
args: "1.1.1.1 tls://8.8.8.8:853 https://dns.google/dns-query quic://1.1.1.1:853 h3://cloudflare-dns.com/dns-query"

Selection & health behavior

  • ReDNS tracks per-upstream latency (EMA) and consecutive error streaks, and prefers healthy, low-latency upstreams.
  • With concurrent > 1, several upstreams are queried simultaneously and the best response wins.
  • A UDP response with the TC (truncated) flag is transparently retried over TCP.
  • Secure transports (DoT/DoQ/DoH3) validate certificates against the system webpki trust anchors.
  • Upstream health and metrics are visible in the dashboard and via the metrics API.

When the system resolver is unavailable (e.g. during startup), use dial_addr and bootstrap in the forward plugin to reach DoH/DoT upstreams directly — see the forward page.
