Operations

Day-to-day operational topics: logging, shutdown, service management, performance backends, and security.

Logging

Set the level with log.level (error, warn, info, debug, trace) or the RUST_LOG environment variable, which takes precedence. Use log.file to write to a file instead of stdout. The debug_print plugin logs full query contexts at debug level.

Graceful shutdown

Send SIGINT (Ctrl-C) or SIGTERM (systemctl stop, docker stop). ReDNS stops accepting queries, dumps the cache to disk when persistence is configured, and exits cleanly.

Running under systemd

# /etc/systemd/system/redns.service
[Unit]
Description=redns DNS forwarder
After=network-online.target
Wants=network-online.target

[Service]
ExecStart=/usr/local/bin/redns start -c /etc/redns/config.yaml
Restart=on-failure
AmbientCapabilities=CAP_NET_BIND_SERVICE

[Install]
WantedBy=multi-user.target

io_uring UDP backend

On Linux, ReDNS can use io_uring for the UDP receive path: cargo build --release --features io-uring, then redns start --udp-backend io-uring (or set udp_backend: io-uring per server). If io_uring is unavailable on the running kernel, ReDNS logs a warning and falls back to epoll automatically.

ASN database

The asn matcher needs a MaxMind-DB file with ASN records. Point asn_db at your own files, or rely on the default: on first use ReDNS downloads origin-asn.mmdb (~10 MB, sapics/ip-location-db) and caches it under $XDG_CACHE_HOME/redns/ or ~/.cache/redns/. Downloads are atomic — an interrupted download never leaves a corrupt database behind.

Security notes

  • Bind the API and dashboard listeners to 127.0.0.1 unless you need remote access — they expose operational data.
  • The DNS listener is unauthenticated by design; do not expose port 53 to untrusted networks without additional filtering.
  • ReDNS validates upstream TLS certificates with the system webpki trust anchors.
  • Port 53 is privileged: run as root, grant cap_net_bind_service, or use the systemd unit above.
